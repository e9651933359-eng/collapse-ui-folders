# Федерация в чатах

Демо-сценарий доступен по `/federation`. Обычные чаты остаются по `/chats`; оба маршрута используют один `ChatExperience`, оболочку, списки, сообщения и Message Editor.

## Правила продукта

- Федерация — доверенная связь двух организаций без объединения их в одну организацию.
- Признак показывается перед именем сотрудника другой организации: в списке чатов, шапке, у автора сообщения и в профиле.
- В личном чате предупреждение над полем ввода постоянно, не закрывается и использует компактную однострочную композицию на warning-фоне.
- В группах и каналах компактная плашка показывает число внешних участников. Клик открывает центрированную модалку с поиском и списком внешних участников.
- В шапке федеративной группы или канала подпись содержит только общее количество участников. Состав организаций хранится в данных сценария и показывается в федеративных уведомлениях и списках участников.
- `/federation` сохраняет заголовок «Чаты» и общий продуктовый sidebar без отдельной точки входа Федерации.
- Связь A–B не открывает транзитивный доступ B–C.
- Недоступную организацию нельзя выбрать; интерфейс показывает первую актуальную причину до действия.
- Статус присутствия внешнего сотрудника не показывается.

## Архитектура

- `features/federation/model.ts` хранит доступность, организации и число внешних участников.
- `features/federation/mockData.ts` содержит только демо-данные федеративных чатов.
- `FederationNotice` использует компактный вариант Message Editor: в группе или канале число участников выделено цветом `Background/Solid/Secondary/Type8` из Figma `6932:43530`.
- `FederationParticipantsModal` собирается из общих `ModalPage`, `SearchField`, `ListItem`, `Avatar` и открывается на overlay-уровне оболочки, а не внутри Message Editor.
- UI Kit получает только необязательный `federation`-prop; значение по умолчанию `false`, поэтому `/chats` не меняется.
- Повторяющаяся связка текста и иконки вынесена в общий `FederationLabel`.
- В продуктовой строке `ChatListItem` иконка расположена перед названием; это локальная композиция строки, не изменение позиции во всех `FederationLabel`.
- `FederationCreateFlow` содержит state machine создания личного чата, группы, канала и добавления участников. Для группы после действия в стартовом экране сначала выбираются участники, затем заполняются параметры новой группы. Экран собирается из `ModalPage`, `SearchField`, `DropField`, `TextField`, `TextArea`, `Uploader`, `Switch`, `CheckBox`, `Avatar` и `Button`.
- Созданная группа использует общий `Avatar` с вариантом `Filled=false`: светлая акцентная заливка и тёмная монограмма, как в Base Figma `Avatar/User` (`8654:86603`).
- Градиентные монограммы в Base Figma не подтверждены и в демонстрационных данных федераций не используются: user/group получают solid tint с `Filled=false`, channel — solid-заливку.
- Демо-чаты используют локальные растровые аватары через существующий `Avatar.image`: личные и групповые чаты остаются круглыми, канал использует squircle. Изображения являются демонстрационными ассетами, а не правилом Collapse из Figma.
- Выбранные участники отмечаются только чекбоксами в списке и числом на кнопке действия; отдельный ряд тегов или аватаров не показывается.
- Участники выбранной организации сортируются по имени в алфавитном порядке после применения поиска.
- В стартовом экране «Начните общение» и в выборе участников прокручивается только список. Шапка `ModalPage` с действиями, `SearchField` и `DropField` организации остаются на месте: экраны со списком используют общий `ModalPage scroll="content"`. Экран параметров группы или канала по-прежнему прокручивается целиком. Стили `federation.css` подключаются в каждом федеративном компоненте, который их использует, поэтому stories показывают модалки так же, как в продукте. Storybook: `Federation/CreateFlow / StartChat`.
- В демо-данных МТС 30 сотрудников, чтобы проверить прокрутку. У сотрудников есть фотографии через `Avatar.image`; монограмма остаётся запасным вариантом. Портреты — локальные копии демо-фото randomuser.me в `public/assets/avatars/people/`, а не ассеты Collapse из Figma.
- В выборе участников вся строка является checkbox-контролом: клик по аватару, имени, почте или свободной области переключает участника.
- `ModalPage height="viewport"` оставляет по 40 px сверху и снизу по узлу Figma `6969:61874` для длинных списков. Параметры новой группы используют общий вариант `height="content"` и адаптируются под содержимое.
- Меню общего `DropField` занимает ширину поля, поэтому экран федерации не переопределяет его размеры.
- Контентный slot выбора участников использует `Spacing/L` со всех сторон и `Spacing/S` между поиском, организацией и списком; нижний отступ сохраняется после последнего пункта.
- `FederationParticipantProfile` использует центрированное размещение общей `ModalPage`; данные сотрудника остаются в feature-модуле. В личном чате профиль открывается кликом по идентификационной части шапки.
- Клик по идентификационной части шапки открывает профиль для любых чатов (общая логика `ChatExperience`, не только Федерация): группа → «Профиль чата», канал → «Профиль канала», личный чат → профиль пользователя. Из профиля чата «Участники» ведут к списку **всех** участников по алфавиту (администраторы — отдельным разделом), клик по участнику — его профиль с «Назад». Внешние участники в списке помечены иконкой Федерации, в профиле — `FederationTag`; профиль чата с внешними показывает «Есть участники из другой организации». Оранжевая плашка над редактором по-прежнему открывает только список внешних участников (Figma `6932:43530`).
- Состав участников поставляет необязательный prop `getMembers`; без него используется демо-состав `features/chat/profile/members.ts` (допущение: в данных чатов нет списка участников, контакты личных чатов — демо). Вкладки «Медиа / Файлы / Ссылки» строятся из сообщений чата; месяцы, поиск и «…» из макета 6932:42733 не реализованы.
- Профиль участника (Figma `40000074:62312`): `Avatar` 124 px, имя Head/S, username, `FederationTag`, кнопка «Чат» (`ActionCard`) на всю ширину, группы «Контакты» и «Дополнительная информация» из `ListItem interactive={false}` (view-only: `<div>`, без hover/active). Email и телефон копируются кнопкой. Кнопка «Назад» возвращает в список участников (`onBack`). Техническое допущение: username = часть email до `@`.
- Тег «Участник из другой организации» везде рисуется общим `FederationTag`. Аудит: в профиле участника заменён; `FederationNotice` (полоса над редактором) и `FederationLabel` (иконка при имени) — отдельные элементы, не теги. Профиля канала в коде пока нет; при его создании использовать `FederationTag`.
- Общий `ChatList` получил только необязательное действие кнопки создания, а `ChatExperience` — композиционный overlay-slot и операции добавления/обновления чата. Без этих props `/chats` сохраняет прежнее поведение.

## Реализованные сценарии

- выбор организации и создание личного чата с внешним сотрудником;
- создание группы, выбор внутренних или внешних участников;
- создание публичного или приватного канала и ограничение внешних организаций для публичного канала;
- добавление участников в существующую группу или канал;
- просмотр и поиск всех внешних участников из плашки Message Editor;
- предупреждение при добавлении первого внешнего участника;
- полный и сокращённый профиль внешнего сотрудника из списка участников;
- недоступная организация с первой актуальной причиной.

## Условия демо

Раздел видим, если включён feature flag, организация подключена и у пользователя есть право просмотра. Создание доступно роли `manage` при наличии хотя бы одной подключённой организации. Условия изолированы в `getFederationAvailability` и могут быть заменены серверными данными без изменения UI.

Демо-список дополнен двадцатью сценариями для проверки прокрутки и фильтров: пять каналов, личные и групповые чаты. Федеративные и обычные записи перемешаны; для федеративных записей заданы данные внешних участников. Каждая переписка содержит серию входящих и исходящих сообщений, ответы, реакции и местами изображения, чтобы ленту можно было прокручивать.
